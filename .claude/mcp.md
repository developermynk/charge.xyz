# MCP Rules

Always prefer MCP over guessing.

If repository information is needed:

Use GitHub MCP.

Never hallucinate repository structure.

---

If documentation is required:

Use documentation MCP.

Read official docs before implementation.

Never rely on memory if docs are available.

---

If package APIs are unknown:

Search MCP.

Do not invent APIs.

---

If searching code:

Use repository search.

Never manually scan entire repository.

---

If environment variables are referenced:

Locate existing env usage first.

Do not invent variable names.

---

If CI exists:

Read workflow before changing build process.

---

If package.json exists:

Inspect dependencies before installing new ones.

Avoid unnecessary dependencies.
